Despliegue de aplicación web (Java + Spring Boot) con Docker en Render

Hola que tal comunidad DevOps, al terminar el curso de Docker, decidí aplicar lo aprendido y realizar el despliegue de una aplicación web + base de datos en un servicio en la nube.

El proceso realmente es simple, pero lo contaré con algo de detalle:
[ol:1]

  • Tomé los elementos más básicos de un proyecto en el trabajé hace un tiempo para una transportista, dejando únicamente operaciones de lectura y escritura hacia la base de datos desde una página web, \(bueno, también incluye un update simple\)
  • Empaqueté la aplicación en una imagen de docker creando su respectivo Dockerfile, aplicando el multi-stage, sanitización con variables de entorno y creando un usuario sin privilegios \(este archivo va a ser de suma importancia para el despliegue en la nube\)
  • Creé un archivo compose.yaml para desplegar localmente el servicio de la base de datos \(inicialmente usé MySQL, pero terminé migrando a PostgreSQL, más adelante aclararé esta decisión\) y el servicio donde viviría la imagen con la aplicación
  • Al validar que estos servicios funcionan y se comunican entre sí localmente, pasamos con la creación del pipeline CI/CD, si bien esto se puede desplegar en AWS con los servicios de EC2+ECR o bien solamente usando EC2+el compose, busqué una alternativa para que todo el que quiera replicarlo pudiera hacerlo de forma gratuita y sin las limitaciones de tiempo de los servicios de sandbox que aquí se nos proveen, así que decide desplegar la aplicación en render
  • Render en su capa gratuita no permite exponer puertos personalizados para levantar los servicios de una base de datos de MySQL \(por ejemplo\), sin embargo ya incluye un servicio de PostgreSQL, es aquí donde tomé la decisión de migrar de MySQL a PostgreSQL, aunque para automatizar este despliegue se requieren algunas pre-condiciones
    ✅ Necesitas crear primero el servicio de la base de datos de PostgreSQL en render, ya que genera sus propias claves de forma automática, también permite crear usuarios y contraseñas personalizadas pero el servicio debe estar arriba primero
    ✅ Con la base de datos arriba, podemos crear ahora el Web Service para la aplicación de Java en render y configurar las variables de entorno que consumirá, mismas que están asociadas al servicio de la base de datos
    ✅ A este Web Service también se le tiene que configurar un Deploy Hook \(o puedes tomar el que se configura por default\) y en el repositorio de GitHub añadirlo como secreto, lo mismo para tu usuario de DockerHub y el PAT \(Personal Access Token\)
    6. Cumpliendo las pre-condiciones, ahora sí, solo resta crear el pipeline, que incluye verificación y compilación del código, verificación de la imagen de Java+Spring Boot \(Dockerfile\) y de los servicios en conjunto \(compose.yml\), publicación de imagen en DockerHub y por último despliegue en Render
