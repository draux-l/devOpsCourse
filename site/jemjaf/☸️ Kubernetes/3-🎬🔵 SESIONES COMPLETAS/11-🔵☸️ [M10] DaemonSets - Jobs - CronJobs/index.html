☸️[M10] Kubernetes en VIVO: PV, PVC Y STORAGECLASS

Dejamos atrás el clásico Deployment para dominar los controladores diseñados para tareas específicas, mantenimiento y procesos de fondo:

  • DaemonSet \(1 Pod por Nodo\): A diferencia de un Deployment donde el Scheduler decide dónde poner las réplicas, el DaemonSet garantiza que corra exactamente 1 copia de tu Pod en cada nodo del clúster. Si escalas y agregas un nodo nuevo, crea una copia ahí automáticamente. Ideal para agentes de monitoreo, logs o redes.
  • Job \(Tareas que terminan\): Un Deployment asume que tu app debe correr para siempre y la reinicia si se detiene. El Job está diseñado para procesos finitos \(migraciones de BD, reportes, procesamiento por lotes\). Cuando la tarea finaliza con éxito \(exit 0\), se marca como Completed y no se reinicia. Obligatorio usar restartPolicy: Never o OnFailure.

    CronJob \(Tareas programadas\): Crea Jobs automáticamente basándose en un horario con sintaxis Cron estándar \(* * * * *\). Perfecto para respaldos automáticos nocturnos \(ej. un pg_dump de base de datos hacia un PVC\).
    Control de Concurrencia \(concurrencyPolicy\):

    • Allow \(default\): Permite que varias ejecuciones corran al mismo tiempo si la anterior se demora.
    • Forbid: Si la ejecución anterior sigue corriendo, se salta la nueva \(la configuración recomendada y más segura para evitar corromper backups de bases de datos\).
    • Replace: Cancela la ejecución anterior que sigue corriendo y lanza una nueva.

      ¡A repasar la clase y automatizar sus tareas de mantenimiento en el clúster! 🚀 Dudas en los comentarios.
