☸️ [M4] Kubernetes en VIVO: ReplicaSet, Deployment y HPA

👋 Ya tienen disponible la grabación del Módulo 4. En esta sesión dimos el salto crítico: dejamos de crear Pods sueltos \(que si mueren, no vuelven\) y aprendimos a usar los controladores que gobiernan la alta disponibilidad y las actualizaciones sin cortes en producción.

Aquí tienen el resumen exacto de lo que trabajamos:

  • ReplicaSet \(El vigilante\): Entendimos cómo el ReplicaSet asegura que siempre haya un número exacto de réplicas corriendo mediante su loop de reconciliación. Si un Pod muere, crea uno nuevo para reemplazarlo.
  • Deployment \(El estándar de oro\): Vimos por qué casi nunca creamos un ReplicaSet a mano: el Deployment es una capa superior que lo envuelve y le añade superpoderes. Probamos su principal ventaja: los Rolling Updates, que nos permiten actualizar la imagen de nuestra aplicación de forma gradual y sin generar downtime.
  • Rollback \(El botón de pánico\): ¿Qué pasa si desplegamos una versión con errores? Vimos cómo ejecutar un kubectl rollout undo para revertir al instante a la versión estable anterior.
  • Probes \(Liveness y Readiness\): Explicamos la diferencia crítica entre un contenedor que "sigue vivo" y uno que "está listo para recibir tráfico". Configuramos nuestras pruebas de salud \(livenessProbe para reiniciar pods colgados y readinessProbe para pausar el tráfico si la app aún no carga\).
  • Escalado Manual vs HPA \(Autoescalado\): Primero escalamos el Deployment "a mano" con kubectl scale y vimos por qué tener múltiples réplicas \(al menos 2 o 3\) es vital para tolerar la caída de un nodo entero. Luego, instalamos el metrics-server y configuramos nuestro primer HorizontalPodAutoscaler \(HPA\) para que Kubernetes ajuste automáticamente el número de réplicas midiendo el consumo real de CPU.

    Dejo el comando para el pod de incremento de carga:
    # Run this in a separate terminal
    # so that the load generation continues and you can carry on with the rest of the steps
    kubectl run -i --tty load-generator --rm --image=busybox:1.28 --restart=Never -- /bin/sh -c "while sleep 0.01; do wget -q -O- [http://popshop-api](http://popshop-api); done"

    Este es uno de los módulos más importantes del curso porque es exactamente como operarás aplicaciones en el mundo real.

    ¡A practicar esos rollouts y a ver cómo sus Deployments se curan solos!
